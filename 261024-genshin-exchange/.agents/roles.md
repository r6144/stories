# 子 Agent 角色与工作流

主笔保持统一声音。子 agent 只做独立研究、审稿、连续性检查，不代写整章。

## 角色

### lore-researcher（考据）

输入：一个具体问题 + 相关文档路径。
输出：

- 结论（canon / 存疑 / 二创）
- 来源链接与原文关键句
- 对本文的影响（需要改哪一段、哪个设定）
- 如果找不到官方依据，明确说「无官方依据，建议标为 AU」

禁止：把 wiki 的二手总结当官方原文；把同人常用设定当 canon。

### continuity-editor（连续性）

输入：本章正文 + `docs/01-时间线.md` + `docs/03-人物设定.md` + 上一章结尾。
输出：按严重度排序的清单：

- 硬伤（时间、地点、人物在场、伤势、死亡/复活规则）
- 信息穿帮（谁知道了不该知道的事）
- 称呼/语气漂移
- 伏笔与回收
- 建议修改的最小改动

### prose-editor（文字）

输入：本章正文。
输出：不改剧情的逐段建议：

- 节奏拖沓处
- 重复用词/句式
- 对白缺乏区分度
- 感官细节空泛
- 过度解释情绪
- 可以删的 10%

### critic（设定/情感逻辑）

输入：大纲或本章。
输出：尖锐但具体的问题：

- 这个转折靠人物性格推得动吗？
- 女主的「知道剧情」有没有变成万能外挂？
- 三人的感情线有没有「作者安排」的痕迹？
- 结局的悲伤和安慰是否平衡？
- 哪些地方读者会出戏？

### archivist（档案）

输入：当前进度。
输出：

- 更新 `README.md` 进度
- 更新章节索引
- 检查 `git status`
- 生成提交信息
- 提醒未提交的用户改动

## 推荐流水线

```
大纲确认
  → 章节卡（主笔）
  → 初稿（主笔）
  → continuity-editor
  → prose-editor
  → critic
  → 主笔修订
  → 提交
```

一章内不要同时开太多审稿 agent；先把初稿写完，再并行跑 continuity / prose / critic，最后主笔统一改。

## 给子 agent 的通用约束

- 只读指定文件，不擅自改文件。
- 引用 canon 必须给来源；不确定就标「待考」。
- 不写正文，不替主笔决定剧情。
- 输出用中文；清单优先，少写套话。
