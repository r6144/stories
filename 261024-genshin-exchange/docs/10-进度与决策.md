## 上下文原则

- **每章一个新会话**；不要在同一个会话里连续写多章。上下文越长，模型越容易受最近一段文字的影响；上一章全文在场，下一章就会不自觉模仿它的句长/段落。
- **每章上下文等长、同序**。不要让「后面剧情更多」变成「写作包更长」；剧情多就压缩成事实，不扩写上下文。
- **不贴上一章全文**；用 300–500 字事实账本代替。需要接续具体场景时，只给 1–2 句关键对白/动作，不给整段。
- **风格靠固定声音锚点，不靠指标**。指标是事后诊断，不是写作目标；对着指标改文会把文字磨平。
- **初稿后先核实剧情逻辑**：因果链、人物动机、信息状态、时间线。声音/段落只在明显漂移时处理；不要为字数、段落平均长度等量化指标改文，除非用户明确要求。
- **审稿并行，不叠加**：continuity / voice / canon 三个只读子 agent 可以并行；不要一个接一个把整章和历史反复喂给模型。（**2026-10-25 起暂停使用子 agent**；恢复前先问用户。子 agent 长时间无响应或有疑问时，先通知用户，不要轻易取消。）
- **git 写操作报权限错误**：直接通知用户授权，或说明命令与报错让用户手动处理；不要用 `write-tree` / `commit-tree` / `update-ref` / `update-index` 等底层命令绕过，也不要进入 `.git` 目录排查。
