# AGENTS.md

## 项目是什么

这是一篇《原神》同人长篇的工作区。标题：**《借来的花神诞祭》**。

核心设定：22 岁的国贸毕业生、深渊主播，在 5.8 前瞻次日（2025-07-19）穿越成荧，在提瓦特生活 1 年 9 个月，促成妮露、纳西妲、芙宁娜的幸福；穿越结束时她回到现实并死亡，原版荧回到提瓦特，赶上三人的婚礼。

目标：11 章，每章 8,000–16,000 字中文。当前处于**第五章初稿完成（审稿暂缓）、第六章待写**的阶段。

## 工作流

1. **考据**：优先官方游戏文本、角色故事、任务文本、官方 PV；其次 BWIKI / HoYoWiki / Project Amber 数据库。每条关键设定记录来源。
2. **区分 canon 与 AU**：所有偏离官方设定的地方，必须在 `docs/05-官设考据.md` 的「AU 改动」表中登记，并写明理由。
3. **章节卡**：写正文前，先补 `docs/08-章节写作包/chXX.md`：地点、时间、在场人物、目标、冲突、转折、结尾钩子、不能忘的 canon/信息状态。
4. **初稿**：一次写一章，每章 8k–16k 字，作为写作目标，不是验收指标；不跳场景；不写系统面板。读者默认熟悉 canon，3.0/3.2/3.6/4.2/4.7 的任务流程一笔带过，只写女主视角的增量。篇幅服从章节完整，初稿后不为字数回头删改。
5. **剧情逻辑核实（初稿后第一件事）**：因果链、人物动机、谁知道/不知道什么、时间/地点/伤势/承诺/道具；发现逻辑断裂先改结构，不先润色。这一遍是现阶段的主要工作。
6. **声音校对（按需）**：读 `docs/09-声音与节奏.md`，只在明显声音漂移、读起来不像时做；不为字数、段落平均长度、对话比例等量化指标改文，除非用户明确要求。
7. **提交**：每完成一个阶段或一章提交一次 git；提交信息格式见下。

### 可用的子 agent 角色

详见 `.agents/roles.md`。建议用法：

- `lore-researcher`：独立核对某段 canon，返回来源与结论。
- `continuity-editor`：只读本章 + 相关文档，找连续性与人物 OOC。
- `prose-editor`：只改文字，不改剧情。
- `critic`：专门找设定漏洞、情感逻辑问题、结局是否成立。
- `archivist`：整理文档、章节索引、提交记录。

**不要让子 agent 代写整章正文。** 子 agent 用于独立研究与审稿，主笔保持统一声音。

**现阶段暂停使用子 agent**（2026-10-25 起：上一轮 continuity 审稿超时，收益有限）。以后如需恢复，先与用户确认；不要轻易取消运行中的子 agent，若长时间无响应或有疑问，先通知用户。

## 上下文管理（控制费用）

- **每章一个新会话**；不在一个会话里连续写多章。正文的漂移往往来自「上下文越来越长 + 上一章全文的惯性」，不是模型突然不会写。
- **固定上下文配方**（每章一样长、一样顺序）：
  1. `AGENTS.md`（规则）
  2. `docs/09-声音与节奏.md`（约 1k–1.5k 字，固定）
  3. `docs/08-章节写作包/chXX.md`（约 3k–4k 字，固定模板）
  4. `docs/10-进度与决策.md` 的「事实账本」（约 300–500 字：上一章发生了什么，不贴原文）
  5. 本章需要的 1–2 个 canon 片段（不超过 500 字）
- **不要加载**：上一章全文、整份大纲、整份 `05-官设考据.md`、之前的对话历史。上一章的句子会把手感带偏；事实账本足够接续。
- **不要**在章与章之间比较「段落平均长度/对话比例」；这些数字会诱导模型为了指标改文。初稿后以剧情逻辑核实为主，声音校对只在明显漂移时做。
- 审稿用子 agent：`continuity-editor` / `prose-editor` / `critic` 只读本章 + 写作包 + 声音锚点 + 事实账本，不读整段历史。（**现阶段暂停使用子 agent**，见「可用的子 agent 角色」。）
- 每章完成后更新 `docs/10-进度与决策.md`：事实账本、下一章钩子、已改设定；不要贴正文。
- 不在正文里重复 canon 剧情；读者默认玩过/熟悉原作，复述会浪费字数和上下文。

## Canon 规则

- 官方中文译名优先：死域、蕈兽、妮露、纳西妲、芙宁娜、厄歌莉娅、若娜瓦、命运的织机、甘露花海、万种母树、花灵、斯露莎、祖尔宛、伽乌迦那、慈心、染境、祭水之仪、焚真之天象。
- 写前读 `docs/05-官设考据.md` 的「二创陷阱」；不要把二创当 canon。
- 四条不可越过的红线：
  1. 花神诞祭是虚空制造的共享梦境，不是时间循环；妮露是梦境主体。
  2. 神像复活是唯一特例：纳西妲感知/上报，若娜瓦按天理规则借命；不是通用复活术，也不是纳西妲的能力；妮露不知道神像能做什么。
  3. 女主真的死；不复活、不转生、不变系统/神明。
  4. 女主对三人没有浪漫箭头；三人是无性浪漫；帕丽莎是新花灵，不是人类婴儿/女主转世。
- 时间线以 `docs/01` 为准；角色知道什么以 `docs/03` 信息状态表为准；荧只知道游戏存在、不玩、不主动看 3.0 后剧情。
- 林晚的知识截止 5.8 前瞻；**6.6（月之七）的婕德后续/柯莱花神碎片不在她的知识范围内**，本文不写、不引用、不矛盾。
- 其他 canon 细节、AU 登记、易错点，全部以 `docs/05` 为准。

## 文体规则

- 第三人称限知，过去时；主视角女主；现实线荧的限知；短插曲（纳西妲/若娜瓦/妮露）用分隔符标出，不解释全部。
- 正文里的女主一律称「林晚」，不用「女主」作叙述称呼；「女主」只用于文档、表格和创作讨论。
- 每章 8k–16k 字，作为写作目标，不是验收指标；对白与叙述交替。章节完整优先于字数，不为凑数或压数删节拍；初稿完成后不为字数回头删改。
- 文笔优美、偏诗意；不要写过多过散的短段落。
- 正文引号用普通“”，不用「」。
- 提瓦特场景不写游戏 UI、等级、HP、抽卡；不写「系统提示」「叮」。
- 感官优先；女主的游戏术语要立刻被现实翻译/打脸。
- PG-13；三人无性浪漫；不写性/身体细节；纳西妲不幼态化；帕丽莎不是人类婴儿。
- 女主不说脏话；网络梗每章不超过 3–4 处。
- 数字：日期、时间、金额、确切数量用阿拉伯数字；固定搭配（一下、两下、两件事）可用汉字。
- 其他文体细则（POV、分级、术语）以 `docs/06` 为准；声音/节奏以 `docs/09` 为准。

## Git 规则

- 提交前先 `git status --short`。
- 只 `git add` 本项目目录内的文件；不要动根目录 `.gitattributes` 或其它项目。
- 如果发现**需要修改的文件已有未提交修改**，先提醒用户提交，不要覆盖。
- 提交信息格式：
  - `[setup] 建立项目结构与规则`
  - `[docs] 设定分析 / 时间线 / 大纲`
  - `[ch01] 第一章初稿`
  - `[fix] 连续性修正：...`
- 不 force push，不 reset 用户改动。
- **权限问题**：`git add` / `git commit` / `git status` 等出现权限错误时，**直接通知用户授予权限**；若授权后仍无法解决，说明具体命令与报错，让用户手动处理。**不要**使用底层 git 命令（`write-tree` / `commit-tree` / `update-ref` / `update-index` 等）绕过，也**不要**进入 `.git` 目录排查（包括查看或修改对象、索引、引用、ACL）。
