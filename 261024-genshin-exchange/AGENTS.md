# AGENTS.md

## 项目是什么

这是一篇《原神》同人长篇的工作区。标题：**《借来的花神诞祭》**。

核心设定：22 岁的国贸毕业生、深渊主播，在 5.8 前瞻次日（2025-07-19）穿越成《原神》主角荧，在提瓦特生活一年零九个月；她与妮露、纳西妲、芙宁娜相识，促成三人的幸福，最后在 4.7「睡前故事」期间穿越结束，意识回到现实世界并死亡；原版荧回到提瓦特，在婚礼当天早上于派蒙身边醒来，赶上三人的婚礼。

目标：10 章，每章 9,000–11,000 字中文，总量约 10 万字。当前处于**设定已确认、准备写第一章**的阶段。

## 工作流

1. **考据**：优先官方游戏文本、角色故事、任务文本、官方 PV；其次 BWIKI / HoYoWiki / Project Amber 数据库。每条关键设定记录来源。
2. **区分 canon 与 AU**：所有偏离官方设定的地方，必须在 `docs/05-官设考据.md` 的「AU 改动」表中登记，并写明理由。
3. **章节卡**：写正文前，先补 `docs/08-章节写作包/chXX.md`：地点、时间、在场人物、目标、冲突、转折、结尾钩子、预计字数、不能忘的 canon/信息状态。
4. **初稿**：一次写一章，9k–11k 字；不跳场景；不写系统面板。读者默认熟悉 canon，3.0/3.2/3.6/4.2/4.7 的任务流程一笔带过，只写女主视角的增量。
5. **连续性检查**：时间、伤势、承诺、道具、称呼、人物知道/不知道的信息。
6. **文字校对**：节奏、重复用词、对白区分度、感官细节、canon 口吻；用 `tools/style_metrics.ps1` 对比 `docs/09-风格基线.md`，防止风格漂移。
7. **提交**：每完成一个阶段或一章提交一次 git；提交信息格式见下。

### 可用的子 agent 角色

详见 `.agents/roles.md`。建议用法：

- `lore-researcher`：独立核对某段 canon，返回来源与结论。
- `continuity-editor`：只读本章 + 相关文档，找连续性与人物 OOC。
- `prose-editor`：只改文字，不改剧情。
- `critic`：专门找设定漏洞、情感逻辑问题、结局是否成立。
- `archivist`：整理文档、章节索引、提交记录。

**不要让子 agent 代写整章正文。** 子 agent 用于独立研究与审稿，主笔保持统一声音。

## 上下文管理（控制费用）

- **本会话只做设定/大纲/决策**；正文建议在**新会话**中写，避免每次调用都携带全部历史。
- 新会话开写时，只加载：`AGENTS.md` + `docs/08-章节写作包/chXX.md` + `docs/06-写作规范.md` 的相关节 + `docs/03-人物设定.md` 的当前章人物 + `docs/01-时间线.md` 的当前时间段。不要加载整份 `05-官设考据.md`，除非本章需要核对具体 canon。
- 每章先写 `docs/08-章节写作包/chXX.md`，把「本章需要的全部上下文」压缩到 3k–5k 字；这是给写作用的唯一长上下文。
- 审稿用子 agent：`continuity-editor` / `prose-editor` / `critic` 只读本章 + 写作包 + 相关人物表，不读整段对话历史。
- 每章完成后更新 `docs/10-进度与决策.md`，记录「已写/待修/下一章钩子」，新会话从这里接上。
- 不在正文里重复 canon 剧情；读者默认玩过/熟悉原作，复述会浪费字数和上下文。
- Windows 默认执行策略可能拦 `.ps1`；跑风格指标用：`powershell -NoProfile -ExecutionPolicy Bypass -File tools/style_metrics.ps1 -Path 正文/ch01.md`。

## Canon 规则

- 官方中文译名优先：死域、蕈兽、妮露、纳西妲、芙宁娜、厄歌莉娅、若娜瓦、命运的织机、甘露花海、万种母树、花灵、斯露莎、祖尔宛、伽乌迦那、慈心、染境、祭水之仪、焚真之天象。
- 不把二创当 canon。常见误区：
  - 「花神诞祭是时间循环」——官方真相是虚空制造的共享梦境，妮露是梦境的「主体」；不是物理时间循环。
  - 「168 次轮回」——游戏文本没有给出确切次数，派蒙说的是「第二十？三十？四十？数不清」。可以写女主的弹幕记忆里有「168」这个梗，但不能当官方设定。
  - 「神像能随便复活人」——游戏里神像是旅行者的重生点，但没有「公开可用的复活术」；本文的复活是特殊情况（纳西妲 + 若娜瓦 + 降临者身体），必须写成特例。
  - 「命运的织机会穿越/换身」——4.7 的织机是「创造/植入记忆」的装置，不是时间机器或换身机器。本文的穿越是织机完成时产生的「线结」副作用，属于 AU 推论。
  - 「芙宁娜是厄歌莉娅的女儿/直接继承人」——厄歌莉娅把水神职责交给芙卡洛斯；芙宁娜是芙卡洛斯造的人类容器。花灵把她视为「厄歌莉娅的继承者」是**信仰/象征层面**的判断，不是血统事实；本文采用「花灵把芙卡洛斯与芙宁娜视为一体两面」的解释。
  - 「神像复活是纳西妲的能力」——纳西妲作为七执政之一，能感知神像附近的情况，发现异常必须及时报告天理/四影；她**不能**随意复活。本文的复活是若娜瓦按天理规则处理的唯一特例。
  - 「花神诞祭的梦可以随便换主体」——本文的「女主的剧透让梦境短暂以她为锚」是 AU 推论；canon 的稳定出口仍是妮露自己意识到「我在做梦」并跳完花神之舞。
- 时间线以 `docs/01-时间线.md` 为准。提瓦特游戏内没有明确纪年，尽量用「花神诞祭前 X 天 / 第 X 个月」这类相对标记，不硬编年份。现实线：2025-07-19 穿越，2027-04-19 结束。
- 角色知道什么、不知道什么，以 `docs/03-人物设定.md` 的「信息状态」表为准。写每章前检查一遍。
- 荧只知道「有一款叫原神的游戏、女主是玩家」，不知道机制、不玩、不主动看 3.0 之后的剧情；她在婚礼当天早上从派蒙/三人口中得知 3.0–4.7 的经历。不要让她提前知道剧情。

## 文体规则

- 第三人称限知，过去时。主视角是女主；现实世界插叙用荧的限知视角，用分隔符或独立小节标出。
- 每章 9k–11k 字；单场景 1.5k–3k 字；对白占比约 35%–45%。
- **文笔优美、偏诗意**；须弥是智慧的国度，学者/神明/花灵的语言可以文绉绉，但妮露/派蒙/芙宁娜的日常口语要平衡。避免流水账，避免过多过散的短段落；段落以 80–200 字为主，允许 200–350 字的长段，不要一句一段。
- 提瓦特场景里不写游戏 UI、等级、HP、帧数、抽卡界面。女主的内心可以偶尔冒出游戏术语，但必须立刻被现实「翻译」或打脸。
- 感官优先：元素力的体感、死域的腐甜味、妮露舞蹈时的水声、纳西妲梦里温度不对的风。
- 不写「系统提示」「叮，获得……」。
- **感情戏 PG-13，且三人是「无性浪漫关系」**：她们相爱、结婚、共同抚养帕丽莎，但没有人类式的生理欲望；不写性、不写身体细节。纳西妲强调 500 岁的神性心智与情感成熟，不幼态化、不性化。女主是直女，对三人是粉丝/同伴/家人的喜欢，不是爱情。
- 帕丽莎是甘露花海的花苞所生的新花灵，不是人类、不是怀孕、不是人形；她的到来是花海的祝福，不是生理结果。
- 避免每章开头大段 recap；读者默认熟悉 canon，3.0/3.2/3.6/4.2/4.7 的任务流程一笔带过，只写女主视角的增量。
- 避免网络梗密集轰炸；女主的吐槽可以有，但每章不超过三四处，且要符合她的年龄和职业。

## Git 规则

- 提交前先 `git status --short`。
- 只 `git add` 本项目目录内的文件；不要动根目录 `.gitattributes` 或其它项目。
- 如果发现**需要修改的文件已有未提交修改**，先提醒用户提交，不要覆盖。
- 提交信息格式：
  - `[setup] 建立项目结构与规则`
  - `[docs] 设定分析 / 时间线 / 大纲`
  - `[ch01] 第一章初稿`
  - `[fix] 连续性修正：...`
- 不 force push，不 reset 用户改动。
