# AGENTS.md

## 项目是什么

这是一篇《プリパラ（美妙天堂）》×《原神》的**跨界同人长篇**工作区。

暂定标题：**《安可》**（书名待确认，见 `docs/07` D1）。

核心设定：**两边都结婚几个月之后**，一场演出让两个世界短暂相接一夜。

- プリパラ 侧：紫京院响 × 绿风芙羽梨 婚后住在芙羽梨的故乡パルプス（阿尔卑斯），学着放羊；法露露 以「情人」的身份与两人同住；三人仍以 Tricolore 同台。
- 提瓦特 侧：纳西妲 × 妮露 × 芙宁娜 三人无性浪漫婚姻，有一个花灵女儿帕丽莎。
- 这一夜之后，门关上；两边各自回到日常，但日常变了。

目标：**9 章**（备选 6 章，见 `docs/07` D4），每章 8,000–16,000 字中文。

当前阶段：**立项与设定分析完成，等用户确认 D1–D15 后开写**。

## 工作流

1. **考据**：优先官方文本（游戏内文本、角色故事、任务文本、官方 PV、动画本篇）；其次 BWIKI / HoYoWiki / 日文维基 / アニヲタWiki 等。每条关键设定记来源，写进 `research/`。
2. **区分 canon 与 AU**：所有偏离官方设定的地方，必须在 `docs/05` 的「AU 改动」表里登记，并写明**理由**与**不能写成什么**。
3. **章节卡**：写正文前，先补 `docs/08-章节写作包/chXX.md`（模板见 `docs/08/README.md`）：地点、时间、在场人物、POV、目标、冲突、转折、结尾钩子、不能忘的 canon/信息状态。
4. **初稿**：一次写一章，每章 8k–16k 字，作为写作目标不是验收指标；不跳场景；不写系统面板。读者默认熟悉两边原作，canon 剧情一笔带过，只写「原作里没有的东西」。
5. **剧情逻辑核实（初稿后第一件事）**：因果链、人物动机、谁知道/不知道什么、时间/地点/伤势/承诺/道具；发现逻辑断裂先改结构，不先润色。
6. **声音校对（按需）**：读 `docs/09`，只在明显声音漂移、读起来不像时做；不为字数、段落平均长度、对话比例等量化指标改文。
7. **提交**：每完成一个阶段或一章提交一次 git；提交信息格式见下。

### 子 agent

**现阶段不使用子 agent 写正文。** 子 agent 只用于独立考据与审稿（`lore-researcher` / `continuity-editor` / `critic`），主笔保持统一声音。要恢复，先与用户确认。

## 上下文管理（控制费用）

- **每章一个新会话**；不在一个会话里连续写多章。
- **固定上下文配方**（每章一样长、一样顺序）：
  1. `AGENTS.md`（规则）
  2. `docs/09-声音与节奏.md`（约 1k–1.5k 字）
  3. `docs/08-章节写作包/chXX.md`（约 3k–4k 字）
  4. `docs/10-进度与决策.md` 的「事实账本」（300–500 字）
  5. 本章需要的 1–2 个 canon 片段（不超过 500 字）
- **不要加载**：上一章全文、整份大纲、整份 `05-官设考据.md`、之前的对话历史。
- 每章完成后更新 `docs/10`：事实账本、下一章钩子、已改设定；不贴正文。

## Canon 规则

### 译名

- **プリパラ 侧**：プリパラ（美妙天堂）、プリパリ、パルプス、ヨーロッパラ、ペルサイユ、紫京院响、绿风芙羽梨、法露露、Tricolore（トリコロール）、卡萨布兰卡、玛格丽特、応援棒（サイリウム）、コーデ（服装）、メイキングドラマ（演出小剧场）、ボーカルドール（歌偶）、プリチケ（プリ券）、パキる（刷卡）、白山羊（官方无名）、トリコ、ユニコン、安藤。
- **提瓦特 侧**：芙宁娜、纳西妲、妮露、帕丽莎、甘露花海、万种母树、伽乌迦那、花灵、斯露莎、祖尔宛、米希尔、拉沙鲁、西摩格、祭水之仪、离渡之仪、灵光、灵光绝唱、慈心、染境、焚真之天象、厄歌莉娅、大慈树王、花神、娜布·玛莉卡塔、净善宫、大巴扎、祖拜尔剧场。

### 红线（不可越过）

1. **两个世界不合并。** 门是例外，只开一夜；没有人留在对方世界；不写「以后常来」「两个世界从此相通」。
2. **芙宁娜 是人类**，早已卸任，没有水神力量；只有神之眼，而且**很弱**。不写她控水、长生、开大。她的价值是「演过五百年」，不是「能打」。
3. **纳西妲 不幼态化**：500 岁神明，有边界、有主动性。她**不能**开传送门、不能复活、不能改世界树；梦桥有限、耗神。
4. **帕丽莎 是花灵**：不是人类婴儿、不是谁的转世；不吃喝、几乎不睡；离开甘露会衰弱（AU）。
5. **法露露 是ボーカルドール**：不是人类女孩、不是 AI、不是宠物；实体化有时限（AU）。
6. **响 是女性**。她接受自己的女性身份；「兄」是别人给她的称呼，不是身份。不写「其实是男人」、不写性别否定、不写「她其实想当男人」，也不写成作品内的「非二元」明示。
7. **妮露 的「花神继承人」**只给美貌、舞蹈、直觉，没有力量/神谕/使命；她本人不知道。
8. **两组关系都是知情、自愿、无性的**。不写争宠、雌竞、「谁才是真爱」；芙羽梨 不吃醋，法露露 不抢人；妮露 与 芙宁娜 是挚友不是情敌。
9. **不改两边 canon 的结局**：不写响 退隐、芙宁娜 复辟、纳西妲 卸任、法露露 变成人；只写缝隙里的关系。
10. **语言**：场内（舞台/プリパラ 领域）自动通意；场外不通（D12）。

### 其他

- 写前读 `docs/05` 的「二创陷阱」。不要把二创当 canon（尤其：响 的父母**没有死**；妮露 没有花神之力；**花灵不是「三位母亲」生的**——canon 只有厄歌莉娅的甘露＋西摩格的灵光，「三条来路」是本项目设定 A9；祭水之仪不需要水神之力）。
- 角色知道什么，以 `docs/03` 的知情矩阵为准。
- 两边的大事件（4.2 审判、3.6 花神书、三期神偶像 GP）结果不改，只提到，不复述。

## 文体规则

- **第三人称限知，过去时**；每章一个 POV（具体方案见 `docs/07` D3）。不写「其实纳西妲早就知道……」。
- 每章 8k–16k 字，写作目标不是验收指标；章节完整优先，初稿后不为字数回头删改。
- 文笔优美、偏诗意；不要写过多过散的短段落；一段只做一件事。
- 正文引号用普通“”，不用「」。文档里可以用「」。
- 不写游戏 UI、等级、HP、抽卡、命座、圣遗物；不写「系统提示」「叮」；プリパラ 的界面也不写成系统面板。
- 感官优先；先身体，后情绪。
- **PG-13**：可以牵手、拥抱、额头碰额头、告白；不写性/身体细节。多边关系写知情同意与边界，不猎奇。
- 数字：日期、时间、金额、较大的确切数量用阿拉伯数字；固定搭配用汉字。
- 两边正文都**不写月份/季节/公元年**：用「演出前三天」「那一夜」「天亮之前」「花期的最后几天」。
- 不说脏话；网络梗每章不超过 3 处。
- 不写「原作复述」：祭水之仪、Tricolore 的演出、4.2 审判，都用侧写与跳跃，只写主观体验与关系增量。
- 日/法文原词：每章不超过 3 处，且必须让不懂的读者也能读懂语境（如「まほちゃん」的处理见 D10）。

## 工具调用规则

- 为减少调用次数、节省时间和费用，多个独立的工具调用请尽可能放在同一条 assistant 消息里一次发出；每次调用独立返回成功或失败，一个失败不取消同批其他调用。
- 这条也适用于检查与写入：能并行的读取/搜索一次发出；有依赖的写文件按顺序来。
- **禁止用 PowerShell 做中文文本的批量替换/重写**（PS 5.1 默认按 ANSI 读写，会毁掉 UTF-8）。中文文档一律用编辑工具改。

## Git 规则

- 提交前先 `git status --short`。
- 只 `git add` 本项目目录内的文件；不要动根目录 `.gitattributes` 或其它项目。
- 如果发现**需要修改的文件已有未提交修改**，先提醒用户提交，不要覆盖。
- 提交信息格式：
  - `[setup] 建立项目结构与规则`
  - `[docs] 设定分析 / 考据 / 待确认问题`
  - `[ch01] 第一章初稿`
  - `[fix] 连续性修正：...`
- 不 force push，不 reset 用户改动。
- **权限问题**：`git add` / `commit` / `status` 出现权限错误时，直接通知用户授权；不要用底层 git 命令绕过，也不要进 `.git` 目录排查。
